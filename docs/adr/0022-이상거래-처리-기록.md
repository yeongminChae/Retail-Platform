# ADR-0022 이상거래 처리는 ERP에 담당자 · 처리 내용과 함께 기록하고 실제 조치는 업무로 둔다

- 상태: 대체됨 (ADR-0037)
- 날짜: 2026-11-20
- 관련 시스템: ERP, Payment Server

## 맥락
ADR-0021에서 되돌리기 실패 건(POS_APP 이상거래 + Payment Server `MANUAL_REVIEW`)을 ERP에 모아 수기로 처리하기로 했다. 남은 미정은 두 가지였다: 수기 처리 수단, ERP에서 완료를 기입했을 때 Payment Server에도 종결을 남길지.

## 선택지
**Payment Server 쪽 종결 기록**

| 선택지 | 장점 | 단점 |
|---|---|---|
| ERP에만 기록 | Payment Server 변경 없음. 가장 단순 | Payment Server의 `MANUAL_REVIEW`는 계속 남음 |
| Payment Server에 수기 종결 API 추가, ERP가 호출 | 양쪽 상태가 맞음 | Payment Server 기능 추가 |
| ERP가 Payment Server DB를 직접 수정 | — | 시스템 경계 위반 (ADR-0023) |

## 결정
- **ERP는 처리 기록만 받는다.** 확인 처리 시 다음을 DB에 저장한다.
  - 처리 완료 여부
  - **담당자** (매장 관리자 또는 전산 담당자)
  - **처리 업무** (무엇을 했는가. 예: 카드 취소 / 조치 불필요 / 기타)
  - 메모, 처리 일시
  - 저장은 감사 로그를 남긴다.
- **실제 조치(카드 취소 등)는 시스템 밖의 업무**다. ERP는 조치를 실행하지 않는다.
  - 현업에서는 VAN사 가맹점 관리 화면 같은 경로로 처리하는 것으로 본다 (**가정**).
  - 이 플랫폼 v1에서는 관리자가 Payment Server 취소 API를 직접 호출한다.
- **처리 완료는 ERP에만 기록한다.** Payment Server의 `MANUAL_REVIEW`는 그대로 두며, 미처리 건수 등 운영 지표는 ERP 기록을 기준으로 센다.

## 대가와 후속 작업
- Payment Server에는 처리된 건도 `MANUAL_REVIEW`로 남는다. ERP는 Payment Server 목록을 가져올 때 이미 처리 기록이 있는 건을 구분해 보여준다.
- 처리 업무의 선택 항목 목록은 ERP 설계에서 확정한다.
- 관리자가 무엇을 해야 하는지 판단할 근거("고객 돈이 지금 빠져 있는가")를 Payment Server가 API로 제공할지는 별도로 정한다 (ADR-0021 후속).
