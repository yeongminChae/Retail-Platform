# ADR-0029 POS는 사번 + 4자리 PIN으로 로그인하고 해시만 배포하며 퇴사는 마지막 근무일 마감 후 반영한다

- 상태: 결정
- 날짜: 2026-11-23
- 관련 시스템: POS 클라이언트, POS_APP, ERP

## 맥락
- 계정(계산원 · 매장 관리자 · 본사)과 역할의 원본은 ERP이고, 점포 서버에는 자기 점포 계정만 내려간다 (ADR-0011).
- POS 로그인은 점포 서버가 받은 사본으로 처리하며 ERP를 호출하지 않는다 (ADR-0013). 계정 차단은 긴급 변경 대상이다 (ADR-0020).
- 계산원 · 관리자는 ERP 화면도 쓴다 (재고 조회 · 이상거래 처리 등, ADR-0010 · 0022).
- ADR-0011은 인증 정보 배포 방식과 퇴사자 차단 방법을 미정으로 두었다.

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| POS 로그인 수단 | POS 전용 PIN, ERP 비밀번호와 분리 | 점포 서버에서 해시가 새도 ERP 계정은 안전. 계산대에서 빠름 | 외울 것이 둘 |
| | POS · ERP 같은 비밀번호 | 단순 | 점포 서버 한 곳이 뚫리면 ERP 계정까지 위험 |
| PIN 길이 | 4자리 (전 역할) | 입력이 빠름 | 해시 유출 시 쉽게 풀림 → 시도 제한 · 분리로 피해를 POS 로그인에 한정 |
| | 관리자만 6자리 | 관리자 권한 보호 | 반품을 전용 창구로 제한하면서(ADR-0030) 관리자 PIN의 금전 위험이 줄어 필요성이 낮음 |
| 퇴사 반영 | 마지막 근무일 점포 마감 후 일배치 | 로그인 중인 사람을 끊을 일이 없음. 영업일 기준과 일치 | 마지막 근무일 당일에는 로그인 가능 |
| | 시각 기준 (예: 23:59) | 직관적 | 일배치는 시각이 아니라 마감 계기로 돈다 (ADR-0020) |

## 결정
- **POS 로그인: 사번 + 4자리 PIN** (전 역할 동일). ERP 화면 로그인은 **별도 비밀번호**다. PIN · 비밀번호는 모두 ERP에서 설정 · 초기화한다.
- **저장 · 배포: 단방향 해시만.** 느린 해시(bcrypt 등, 솔트 포함)로 저장하고, 점포 서버에는 PIN 해시만 HTTPS로 내려준다 (ADR-0020 경로). 원문은 어디에도 저장 · 전송하지 않는다.
- **시도 제한:** PIN을 5회 틀리면 계정을 잠그고, 잠금 해제는 ERP에서 한다.
- **퇴사:** ERP에 **퇴사일 = 마지막 근무일**을 등록한다. 그날 영업일에는 근무할 수 있고, 그날 점포 마감 후 일배치(다음 영업일 적용분)에서 그 계정을 뺀다. 다음 영업일부터 로그인할 수 없다.
- **긴급 차단:** 분실 · 부정행위 등 즉시 막아야 하면 긴급 변경(1분 폴링, ADR-0020)으로 반영한다. 차단을 받았을 때 그 계정이 로그인 중이면 진행 중인 결제만 마무리하게 하고 로그아웃시킨다.
- **v1 계산원 개인정보 범위:** 사번 · 이름 · 소속 점포 · 역할 · PIN 해시. 연락처 · 주민등록번호 등은 수집하지 않는다.

## 대가와 후속 작업
- 4자리 PIN 해시가 점포 서버에서 유출되면 쉽게 풀린다. 피해는 POS 로그인으로 한정되며, 점포 서버 DB 접근 통제로 막는다.
- 본사 회선이 끊긴 동안에는 긴급 차단이 내려가지 않는다. 매장에서 직접 막는 기능은 POS가 판매만 한다는 원칙(ADR-0013)과 충돌해 두지 않으며, 알려진 한계로 둔다.
- 상용화 전 확인 (일반적으로 알려진 요구로 보는 **가정**, 법령 원문 미확인): 비밀번호 일방향 암호화 저장, 개인정보 처리 화면 접근 권한 관리 · 접속 기록 보관, 수집 목적 · 항목 · 보관 기간과 퇴사 후 파기, 고유식별정보 미수집.
