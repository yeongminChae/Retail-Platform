# ADR-0036 역할은 계산원 · 매장 관리자 · 본사 · 전산 담당자 4개로 두고 작업별 권한을 정한다

- 상태: 결정
- 날짜: 2026-11-24
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
- standards.md는 역할 3개(계산원 / 매장 관리자 / 본사)와 민감 작업 감사 로그를 v1에 포함했다.
- 1단계 결정들에서 권한이 걸린 작업이 늘었다: 고객센터 POS 반품 · 재판매(ADR-0031 · 0032), 이상거래 · 대사 처리(ADR-0022 · 0027), Payment 운영 조회 · 수기 조치(ADR-0022 · 0026), 2단계 월마감(ADR-0033), 판매 중지(ADR-0035), 기기 관리(ADR-0011 · 0031).
- 시스템 운영(DB 조회 · 데이터 생성 등)을 맡을 사람이 필요하다.

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 전산 담당자 | 본사 역할에 포함 | 역할 3개 유지 | 업무 권한과 시스템 운영 권한이 섞임 |
| | 4번째 역할 (본사 권한 + 시스템 운영) | 운영 권한을 따로 부여 · 회수 | 역할 하나 추가 |
| 반품 | 계산원 포함 | 고객센터에 관리자 상주 불필요. 기기 제한 + 담당자 책임으로 통제 | — |
| POS 매가 변경 | v1 불가 | 가격 원본 ERP · 스캔 시점 확정 원칙 유지. 할인 설계와 함께 다룸 | 매장 재량 없음 |
| 본사 재고 | 조회만 | 실사 · 조정은 실물이 있는 매장이 책임 | — |
| 기기 사용 중지 | 긴급 / 일반 구분 | 도난 · 오작동은 즉시, 나머지는 다음 영업일 | — |

## 결정
- **역할 4개:** 계산원 / 매장 관리자 / 본사 / **전산 담당자**(본사 권한 전부 + 시스템 운영). 매장 관리자는 **자기 점포만**, 본사 · 전산 담당자는 **전 점포**를 다룬다.
- 점포 서버에는 자기 점포 계정만 내려가므로(ADR-0011) 본사 · 전산 담당자는 POS에 로그인하지 않는다.

- **감사 로그 대상(민감 작업):** 반품 · 하자 예외 · 가격 변경 · 판매 중지 · 이상거래 / 대사 처리 · 마감(POS · 점포 · 강제 · 월) · 기기 유형 변경 / 사용 중지 · 계정 변경 / 차단.
- **기준정보(상품 · 가격 · 계정 · 기기 · 점포)는 DB를 직접 고치지 않고 ERP 화면에서만 바꾼다.** 점포 서버 DB를 직접 고치면 다음 일배치가 되돌리고 감사 로그가 남지 않는다.
- standards.md의 "역할 3개"는 이 결정으로 4개가 된다.

## 대가와 후속 작업
- 전산 담당자의 운영 DB 작업(조회 · 데이터 정정 등)을 허용하는 절차(승인 · 기록 방식)는 미정.
- 매장 관리자가 자기 점포 관리자 계정을 다룰 수 있는지(관리자 간 상호 관리)는 미정 (기본은 본사).
- POS 매가 변경은 할인 · 행사가 설계 때 다시 본다 (`docs/backlog.md`).
