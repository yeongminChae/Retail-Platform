# ADR-0001 형제 레포 구조

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: 전체

## 맥락
POS_APP과 Payment Simulator는 이미 별도 레포로 있고, ERP는 새로 만든다. 세 시스템에 걸치는 설계 문서 · 계약 · 통합 테스트를 둘 곳이 필요하다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 형제 레포 + 상위 레포 | 기존 레포를 그대로 둠. Payment Simulator가 독립 포트폴리오로 남음. 현업에서도 결제 중계 서버는 별도 시스템 | 계약 변경 시 레포 두 곳에 커밋 |
| git submodule | 버전 조합 고정 | 하위 커밋마다 상위에서 포인터 재커밋, `--recursive` 누락 위험. AI와 병렬로 자주 커밋하면 관리 부담 |
| 모노레포 | 시스템 간 변경이 커밋 하나 | 기존 레포 정체성 변경, Gradle 루트 재구성 |

## 결정
형제 레포. 이 레포(Retail-Platform)에는 두 시스템 이상에 걸치는 것(설계 문서 · ADR · `contracts/` · `e2e/` · 통합 실행 환경)만 둔다. 로컬에서는 한 폴더 아래 나란히 clone한다.
