# ADR-0027 ERP 대사는 다음 날 배치로 판정하고 불일치는 수기 처리한다

- 상태: 결정
- 날짜: 2026-11-20
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
- ERP가 하는 대사는 두 가지다.
  - **판매 수신 대사:** 점포 마감 요약 ↔ ERP가 받은 건별 판매의 합 (ADR-0019)
  - **판매 = 결제 대사:** 판매의 카드 결제 금액(posTrx별) ↔ Payment Server가 보낸 빠진 금액 (ADR-0025)
- 두 데이터 모두 아웃박스로 늦게 도착할 수 있다. 점포 아웃박스는 회선 장애 동안 쌓이고(ADR-0014), Payment Server는 5분마다 보낸다(ADR-0025). 마감 요약이 건별 판매보다 먼저 올 수도 있다.
- ERP는 점포 서버에 재전송을 요청할 수 없다 (ADR-0013, 0024).
- ADR-0019는 판정 대기 시간과, 재시도로 풀리지 않는 불일치의 처리 절차를 미정으로 두었다.

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 판정 시점 | 다음 날 정해진 시각에 전 영업일 배치 (T+1) | 늦게 온 데이터로 인한 가짜 불일치가 거의 없음. 현업에 흔한 방식 (**가정**) | 결과가 하루 늦음 |
| | 마감 요약 도착 즉시 | 빠름 | 미도착 데이터 때문에 불일치가 잦음 |
| 불일치 처리 | ERP 목록 + 수기 처리 (ADR-0022 방식) | 이상거래와 처리 방식 통일 | 담당자 업무 |
| 데이터 지연으로 풀린 불일치 | 매일 재판정, 맞으면 자동 해소 | 지연만으로 생긴 건을 사람이 처리하지 않음 | 해소 판정 로직 필요 |
| | 전부 담당자가 닫음 | 단순 | 불필요한 수기 업무 |

## 결정
- **판정 시점:** 다음 날 정해진 시각에 ERP 배치가 전 영업일을 판정한다 (T+1). 구체 시각은 미정 (영업일 마감 이후 충분한 시간을 두고 ERP 설계에서 정함).
- **불일치 유형:**
  - 마감 요약 ≠ 건별 판매 합계 (판매 누락 · 중복)
  - 판매에 카드 결제가 있는데 Payment 상태가 "안 빠짐"이거나 없음
  - Payment 상태가 "빠짐"인데 대응하는 판매가 없음
  - Payment 상태가 "미확정"
  - 한 posTrx에 빠진 승인이 2건 이상 (고객 이중 결제)
- **불일치 처리:** ERP의 **대사 불일치 목록**에 올리고 이상거래와 같은 방식으로 **수기 처리**한다. 담당자 · 처리 업무 · 메모 · 일시를 기록하고 감사 로그를 남긴다 (ADR-0022). 같은 posTrx의 이상거래 기록이 있으면 연결해 보여준다.
- **재판정 · 자동 해소:** 매일 배치에서 열린 불일치를 다시 판정한다. 늦게 도착한 데이터로 맞춰졌으면 **자동으로 해소** 표시한다. 이것은 돈을 처리하는 것이 아니라 데이터 도착을 확인하는 것이다. 다음 날에도 남아 있는 불일치만 담당자에게 알린다.
- 이로써 ADR-0019의 미정 두 가지(마감 요약 판정 대기 시간, 재시도로 풀리지 않는 불일치 처리)는 이 결정으로 정한다.

## 대가와 후속 작업
- 대사 결과는 하루 늦다. 즉시 확인이 필요한 고객 문의는 ADR-0026을 따른다.
- 배치 시각, 불일치 알림 채널 · 기준(standards.md 모니터링 항목)은 ERP 설계에서 정한다.
- 재고 원장 대사(판매 수량 ↔ 재고 변동)는 ERP 내부 대사로 ERP 레포에서 정한다.
- 월마감과 이 일 대사의 관계(미해소 불일치가 있을 때 월마감을 막을지)는 월마감 설계에서 정한다.
