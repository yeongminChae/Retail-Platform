# ADR-0002 거래번호는 POS_APP이 체번하고 결제 건마다 posTrx를 분리한다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS_APP, Payment Server

## 맥락
- POS_APP은 클라이언트가 보낸 `tranNo`를 그대로 쓰고, `SALES`의 유니크 키가 `(STORE_CD, POS_NO, TRAN_NO)`다. 영업일이 없어 날마다 번호가 처음부터 시작하면 충돌한다.
- Payment Server는 `/api/v1/pos-trx/issue`로 `점포-영업일-POS번호-순번` 형식의 posTrx를 DB 시퀀스로 발급하고, posTrx 하나를 승인 하나로 본다(멱등 키).
- 복합결제(카드 여러 장, ADR 범위 밖 POS 결정 Q5)를 하면 한 판매에 승인이 여러 건 생긴다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| POS_APP이 체번 | 판매 원장의 주인이 체번. 결제 서버가 죽어도 현금 판매 지속 | POS_APP에 영업일 · 시퀀스 관리 추가 |
| Payment Server에서 발급 | 기존 기능 재사용 | 현금 판매까지 결제 서버에 의존 |
| 둘 다 따로 두고 매핑 | 유연 | 키가 두 개라 추적이 복잡 |

## 결정
- 거래번호는 POS_APP이 **영업일 + 순번**으로 체번한다. 판매 유니크 키에 영업일을 포함한다.
- Payment Server로 보내는 posTrx는 **`거래번호-결제순번`**이다 (예: 카드 두 장이면 `…-01`, `…-02`).

## 대가와 후속 작업
- 영업일의 정의(자정 기준 / 마감 기준)는 미정 — 일마감 설계에서 정한다.
- Payment Server의 `/pos-trx/issue`는 이 연동에서 쓰지 않는다. posTrx 형식 검증이 있으면 새 형식을 받도록 맞춘다.
