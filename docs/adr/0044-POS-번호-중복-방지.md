# ADR-0044 단말 인증서는 두지 않고 거래번호 유니크 키와 기동 시 POS 번호 점유로 중복을 막는다

- 상태: 결정
- 날짜: 2026-11-25
- 관련 시스템: POS 클라이언트, POS_APP, ERP

## 맥락
- ADR-0011은 "물리 단말과 POS 번호를 묶는 방법(단말 인증)"을 미정으로 두었다.
- 걱정은 두 가지다.
  - **외부 PC가 POS인 척 접속:** 점포 서버는 매장 내부망에 있고 단말은 직원이 설치한다. 판매하려면 계산원 사번 + PIN이 필요하다 (ADR-0029). 발생 가능성이 낮다.
  - **설정 실수로 두 단말이 같은 POS 번호를 씀:** 단말 교체 · 신규 설치 때 실제로 생길 수 있다.
- 거래번호는 점포 서버가 체번한다 (ADR-0002). 같은 POS 번호를 두 단말이 써도 점포 서버가 순번을 하나씩 발급하면 거래번호는 겹치지 않는다. 남는 문제는 두 단말의 시재 · POS 마감이 한 POS 번호로 섞이는 운영 문제다.
- 단말이 고장 · 재부팅 후 다시 켜질 수 있으므로, "접속 이력이 있는 번호를 막는" 방식은 같은 단말의 재기동까지 막는다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 단말 인증서 (mTLS) | 가장 강한 단말 확인 | 발급 · 갱신 · 폐기 · 교체 운영 부담. 막는 위험(내부망 위장)이 낮아 비용 대비 효과 작음 |
| 등록 코드 → 단말 키 | 한 번호에 한 단말을 강하게 묶음 | 등록 절차 · 키 관리 필요 |
| 유니크 키 + 기동 시 점유 확인 | 거래번호 중복은 구조로 차단, 시재 섞임은 가벼운 검사로 차단 | 내부망 위장은 막지 못함 |
| 업무로만 관리 (설치 시 번호 확인) | 구현 없음 | 실수 시 시재 · 마감이 섞임 |

## 결정
- **거래번호 중복은 구조로 막는다.** 점포 서버가 POS 번호별 순번을 DB에서 하나씩 발급하고, 판매의 거래번호(점포 · 영업일 · POS 번호 · 순번)에 **유니크 키**를 건다 (ADR-0002 구조의 명시).
- **같은 POS 번호의 동시 사용은 기동 시 막는다.**
  - 단말은 처음 설치될 때 **단말 ID**(UUID)를 스스로 만들어 로컬에 저장한다. 보안 키가 아니라 같은 기계의 재기동을 구분하는 용도다.
  - 기동 시 점포 서버에 POS 번호 + 단말 ID로 접속한다. 점포 서버는 다음을 확인한다.
    - ERP에 등록되어 있고 사용 중인 POS 번호인가 (ADR-0011, 0031)
    - 그 번호를 **다른 단말 ID가 지금 점유하고 있지 않은가**
  - 다른 단말이 점유 중이면 거부하고, 단말은 **기동을 중단**한다 ("이미 사용 중인 POS 번호").
  - 같은 단말 ID의 재기동은 허용한다. 점유는 단말 ↔ 점포 서버 핑으로 유지하고, 핑이 일정 시간 없으면 해제한다 (단말 교체 시 옛 단말 종료 후 해제되면 새 단말이 사용).
  - 이 핑은 매장 내부망의 단말 ↔ 점포 서버 통신이며 시스템 간 주기 통신(ADR-0042)에 포함되지 않는다.
- **단말 인증서 · 단말 키는 v1에 두지 않는다.** 외부 PC 위장은 매장 내부망 + 계산원 로그인으로 대신하며 알려진 한계로 둔다.
- 보안 쪽 기술 투자는 위험이 더 큰 곳에 쓴다: 카드 단말 암호화(ADR-0006 2단계), 가맹점 ID · 터미널 ID 검증(PAYMENT-SIMULATOR, `docs/backlog.md`).

## 대가와 후속 작업
- 핑 주기 · 해제 시간(제안: 30초 · 2분), 거부 화면, 점유 상태 저장 방식은 POS_APP 레포에서 정한다.
- 오프라인 판매 확장(standards.md 3.1)에서 단말이 서버 없이 체번하게 되면 거래번호 중복을 유니크 키만으로 막을 수 없다. 그때 단말 식별을 다시 설계한다.
