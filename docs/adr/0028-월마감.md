# ADR-0028 월마감은 영업일의 달 기준으로 판매 수신 완료 후 하고 마감한 달은 다시 열지 않는다

- 상태: 대체됨 (ADR-0033)
- 날짜: 2026-11-20
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
- 월마감(재고 이월 · 원가 · 월 집계)은 대부분 ERP 안의 일이다. 이 ADR은 다른 시스템 데이터와 걸리는 부분만 정한다.
- 영업일은 점포 마감 · 개시 기준이며 자정을 넘긴 판매도 그 영업일에 속한다 (ADR-0018). 일 대사는 영업일 기준이다 (ADR-0027).
- 판매는 아웃박스로 늦게 도착할 수 있다 (ADR-0014). 반품은 원거래를 고치지 않고 반품 영업일에 새 반품 판매로 저장한다 (POS_APP 결정 Q4).
- 일 대사의 불일치에는 데이터 미도착과 돈 문제(결제 불일치 · 미처리 이상거래 · 이중 결제)가 섞여 있다 (ADR-0027).

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 월 기준 | 영업일의 달 | 일마감 · 일 대사와 같은 기준이라 숫자가 맞음 | 세무 기준(실거래 시점)과 다를 수 있음 |
| | 판매 확정 일시의 달 | 세무 기준에 가까움 | 일 대사 결과와 월 합계가 어긋남 |
| 선행 조건 | 판매 수신 완료 필수, 돈 문제는 미결로 이월 | 매출 · 재고가 빠진 채 마감하지 않음. 고객 문의 · VAN 확인처럼 끝을 정할 수 없는 일로 마감이 묶이지 않음 | 미결 항목이 다음 달로 넘어감 |
| | 모든 불일치 해소 후 마감 | 깨끗함 | 외부 요인으로 마감이 무기한 지연 |
| 마감 후 도착 데이터 | 다시 열지 않고 다음 열린 달에 반영 | 보고된 숫자가 바뀌지 않음 | 영업일과 반영 월이 다른 행이 생김 |
| | 마감한 달을 다시 염 | 원래 달에 정확히 반영 | 이미 보고된 숫자가 바뀜 |

## 결정
- **월 기준은 영업일의 달**이다. 예: 3/31 영업일에 4/1 00:30 확정된 판매는 3월.
- **월마감 선행 조건:** 그 달의 모든 점포 · 모든 영업일이 **점포 마감 + 판매 수신 완료**(마감 요약 = 건별 판매 합계, ADR-0019 · 0027)여야 한다.
- **돈 문제 불일치는 월마감을 막지 않는다.** 결제 불일치 · 미처리 이상거래 · 고객 이중 결제는 미결 항목으로 다음 달에도 목록에 남긴다. 외부 확인이 필요한 일로 마감을 막지 않는 것이 현업 방식이라는 점은 **가정**이다.
- **마감한 달은 다시 열지 않는다.** ERP의 판매에 두 값을 둔다.

| 값 | 뜻 | 정하는 곳 | 변경 |
|---|---|---|---|
| 영업일 | 판매가 일어난 영업일 | POS_APP (ADR-0018) | 없음 |
| 귀속 마감월 | 이 판매를 반영한 마감월 | ERP가 수신 시 결정 | 결정 후 없음 |

  - ERP는 수신 시 영업일의 달이 열려 있으면 그 달, 이미 마감됐으면 **다음 열린 달**을 귀속 마감월로 정한다.
  - 월 보고서는 귀속 마감월로 집계한다. 영업일과 귀속 마감월이 다른 행은 **전월 조정분**으로 표시한다.
  - 귀속 마감월은 ERP에만 둔다. POS_APP은 영업일만 다룬다.
- 반품은 반품 영업일의 새 판매이므로 원거래가 속한 달을 고치지 않는다.
- POS_APP과 Payment Server는 월마감에 관여하지 않는다.

## 대가와 후속 작업
- 재고 이월 방식, 원가 계산, 월마감 화면 · 권한은 ERP 레포에서 정한다.
- 재고 원장에도 같은 귀속 원칙을 쓸지(늦게 온 판매의 재고 변동을 다음 달에 반영)는 ERP 재고 설계에서 정한다.
- 미결 항목이 오래 남을 때의 운영 기준(기한 · 손실 처리)은 운영 절차로 둔다.
