# 상용화 기준

> 상태: **초안 — 항목별 포함 여부 결정 중.**
> 이 문서가 모든 설계의 판단 기준이다. "다 됐나?"는 여기 체크리스트와 `e2e/` 시나리오 통과 여부로 판단한다.

## 0. 카드 결제 모듈이 시뮬레이터인 것에 대해

결제 쪽 상용화 수준은 **"VAN 어댑터만 교체하면 실연동이 되는 구조"**로 정의한다.

- 실제 VAN · 카드사 전문 송수신은 시뮬레이터로 대체한다 (Payment Server의 `VanGateway` 경계).
- 그 위의 거래 상태 관리 · 멱등성 · 조회 · 망취소 · Recovery · 라우팅은 실연동에서도 그대로 쓰이는 수준으로 만든다.

## 1. 체크리스트

| 구분 | 항목 | 왜 필요한가 | 포함 여부 |
|---|---|---|---|
| 판매 | 마트 POS 판매 · 현금/카드 복합결제 · 전체 반품 | 기본 업무 | 포함 |
| 판매 | 카페 키오스크 (옵션 · 대기번호) | 같은 API로 다른 채널 지원 | 미정 (v1.5 후보) |
| 법·세무 | 과세/면세 구분 | 면세 상품이 섞이면 영수증 · 매출 집계가 달라짐 | 미정 |
| 법·세무 | 현금영수증 | 현금 결제에 필요 | 미정 |
| 운영 | POS 일마감 · 계산원 시재 정산 | 매장 운영의 기본 단위 | 미정 |
| 운영 | 권한 · 감사 로그 | 반품 · 가격 변경 · 이상거래 처리 주체 추적 | 미정 |
| 운영 | 이상거래 처리 화면 · 대사 | ADR-0004의 이상거래를 누가 어떻게 닫는가 | 미정 |
| 장애 | **오프라인 판매** | 서버 · 네트워크 장애 시 판매 지속 여부 (얇은 클라이언트 구조와 충돌) | 미정 — **첫 번째로 결정** |
| 장애 | 시스템별 다운 시 동작 | Payment · ERP가 죽었을 때 POS는 어떻게 하나 | 일부 결정 (ADR-0003) |
| 장애 | 백업 · 모니터링 · 알림 | Recovery 실패 · MANUAL_REVIEW · 이상거래를 누가 언제 아는가 | 미정 |
| 보안 | 카드 데이터 보호 | PCI DSS 원칙 참고 (준수 주장 아님) | 결정 (ADR-0006) |
| 보안 | 개인정보 (회원 · 현금영수증 식별번호 등) | | 미정 |
| 성능 | 피크 시간 동시 POS 대수 · 응답 목표 | DB · Redis 설계 검증 기준 | 미정 |
| ERP | 기준정보 · 구매 · 입고 · 재고 원장 · 월마감 · 대사 | 판매가 재고 · 정산까지 이어짐 | 포함 (모듈별 깊이 미정) |
