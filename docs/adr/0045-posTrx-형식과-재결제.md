# ADR-0045 posTrx 자릿수를 고정하고, 결과 불명 · 망취소 뒤 재결제는 다음 결제순번으로 한다

- 상태: 결정
- 날짜: 2026-11-26
- 관련 시스템: POS_APP, Payment Server, ERP
- 관련: ADR-0002 (보완), ADR-0025 (맥락 정정)

## 맥락
- ADR-0002는 posTrx = `거래번호-결제순번`으로만 정했고, 자릿수는 정하지 않았다.
- PAYMENT-SIMULATOR 확인 (2026-11-25, `main` `2e05320`):
  - Payment Server 승인 DTO와 VAN Simulator는 posTrx를 `^\d{4}-\d{8}-\d{4}-\d{4}$`(점포-영업일-POS-순번)로 검증한다. 결제순번이 붙은 새 형식은 거부된다.
  - 같은 posTrx의 새 승인 시도는 직전 시도가 `DECLINED`일 때만 허용한다. `UNKNOWN_TIMEOUT`(망취소 후 포함)이면 같은 내용은 저장된 결과를 다시 돌려주고, 다른 내용은 `POS_TRX_ALREADY_USED`로 거부한다.
- ADR-0025 맥락은 "결과 불명 → 망취소 → **같은 posTrx로 재결제**"를 예로 들었지만, 위 동작 때문에 현재 코드에서는 그렇게 할 수 없다.
- 대사 · 정산에서 번호를 보려면 번호가 애매하게 건너뛰는 일이 없어야 한다.

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 형식 검증 | 자릿수 고정 | 잘못된 번호를 입구에서 막음. Payment · VAN 형식 검증을 그대로 씀 | POS_APP이 형식을 바꾸면 Payment · VAN도 바꿔야 함 |
| | 문자 집합 · 길이만 | 형식 변경에 영향 없음 | 잘못된 번호가 들어와 대사에서야 발견 |
| 망취소 뒤 재결제 | 같은 posTrx | posTrx 하나 = 고객이 의도한 결제 하나 | 결과를 모르는 시도 위에 같은 키로 새 시도. Payment 멱등 판단 변경 필요 |
| | 같은 거래번호 + 다음 결제순번 | Payment 변경 없음. 확실한 실패(`DECLINED`) 뒤에만 같은 키 재사용 | 한 거래번호에 망취소된 posTrx가 남음 |

## 결정
- **posTrx 형식:** `점포(4)-영업일(8)-POS(4)-순번(4)-결제순번(2)`. 예: `2301-20261126-0003-0042-01`. 영업일은 실제 날짜, 결제순번은 `01`~`99`.
  - Payment Server와 VAN Simulator는 이 형식을 입구에서 검증한다. 형식을 바꿀 때는 새 ADR로 바꾼다.
- **거래번호의 순번은 결과가 확실할 때만 증가한다:** 거래 완료 · 거래 중지 · 보류 · 개점 / 마감처럼 그 거래의 상태가 확정되는 시점이다. 결제 재시도 때문에 거래번호가 바뀌지 않는다 (POS_APP 규칙, 세부는 POS_APP 레포).
- **재결제:**
  - 직전 시도가 `DECLINED`(확실한 실패)면 **같은 posTrx**로 다시 승인한다.
  - 결과 불명 → 조회 → 망취소(ADR-0003) 뒤에는 **같은 거래번호의 다음 결제순번**(새 posTrx)으로 다시 결제한다.
- **결제 상태 전송(ADR-0025)은 posTrx별 그대로다.** 망취소된 posTrx는 "안 빠짐"(망취소 실패면 "빠짐"/"미확정")으로 따로 나간다. 판매에 쓰이지 않은 승인은 ERP 대사가 찾는다 (ADR-0027). ADR-0025의 "같은 posTrx 안 빠진 승인 2건 이상 = 이중 결제"는 `DECLINED` 뒤 재시도 경우에 해당한다.
- Payment Server의 posTrx 발급 API(`/pos-trx/issue` · `/eot`)는 제거한다 (ADR-0002 후속).

## 대가와 후속 작업
- 한 거래번호에 posTrx가 여러 개 생길 수 있다. ERP 화면 · 대사는 거래번호로 묶어 보여 줘야 한다 (ERP 레포).
- 결제순번 상한 99는 한 거래의 결제 시도로 충분하다고 본다 (가정).
- 보류 거래의 번호 처리(보류 해제 시 같은 번호를 이어 쓰는지)는 POS_APP 레포에서 정한다.
- PAYMENT-SIMULATOR 상세: `docs/phase2/01-posTrx-형식.md`.
