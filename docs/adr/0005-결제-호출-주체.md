# ADR-0005 Payment Server는 POS_APP 서버가 호출한다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS 클라이언트, POS_APP, Payment Server

## 맥락
현업 POS는 보통 결제 단말이 VAN 모듈을 통해 VAN에 붙고 POS는 결과만 받는다. POS_APP은 "클라이언트는 입력만 보내고 서버가 상태를 갖는" 얇은 클라이언트 방침이고, 마트 POS와 카페 키오스크가 같은 API를 쓴다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| POS_APP 서버가 호출 | 승인 · 조회 · 망취소 · 보상 취소 · 재시도 판단이 한 곳. 두 클라이언트가 같은 규칙 | 카드 데이터가 POS_APP을 거침 (ADR-0006으로 대응) |
| 클라이언트가 직접 호출 | 현업 단말 구조에 가까움 | 결제 규칙이 마트 · 카페 클라이언트 양쪽에 중복 |

## 결정
POS_APP 서버가 Payment Server를 호출한다.

## 대가와 후속 작업
- 알려진 한계: 실환경에서는 카드번호를 단말과 VAN 모듈이 처리하고 POS 서버는 승인 결과만 받는다. 1단계에서는 카드번호가 POS_APP을 통과하며(저장하지 않음), 2단계에서 단말 암호화로 POS_APP이 평문을 보지 않게 한다 (ADR-0006).
- 설계 근거: 단말 직결 구조에서도 "단말은 승인됐는데 POS가 결과를 못 받는" 불일치가 생긴다. 이 플랫폼은 그 판단을 서버 한 곳에 모으는 것을 목표로 한다.
