# ADR-0034 기준정보는 마감 후 일배치로 받고 긴급 변경 4종만 3분 폴링으로 받으며 가격은 스캔 시점에 확정한다

- 상태: 결정
- 날짜: 2026-11-24
- 관련 시스템: POS 클라이언트, POS_APP, ERP
- 대체: ADR-0020

## 맥락
- ADR-0020은 점포 마감 후 일배치 + 긴급 변경 1분 폴링으로 정했고, "판매 확정 시 가격은 점포 서버가 다시 계산한다"고 적었다.
- 결제가 시작된 뒤 가격을 다시 계산하면 카드 승인 금액과 판매 금액이 어긋난다.
- 긴급 경로를 없애는 안도 검토했으나, 가격 오류 · 리콜 상품이 그날 계속 팔리고 분실 계정이 하루 살아 있어 상용화 기준(standards.md)에서 약점이 된다. 폴링은 점포 → 본사 요청이라 요청 방향 원칙(ADR-0013 · 0024)을 어기지 않는다.
- 요청 수 비용: 점포 50개 · 3분 주기면 월 약 72만 건으로, 클라우드 요청 과금 기준 월 1달러 미만 수준이다 (대략적 요금 기준, **미확인**).
- 바뀌지 않은 내용은 이 ADR에 다시 적는다.

## 선택지
**긴급 변경 수신**

| 선택지 | 장점 | 단점 |
|---|---|---|
| 점포가 3분마다 폴링 (긴급 4종만) | 요청 방향 유지. 단순. 생존 신호로 겸용 | 최대 3분 지연 |
| 1분 폴링 (ADR-0020) | 지연 짧음 | 이 용도에는 잦음 |
| 점포가 연 웹소켓으로 긴급 전달 | 거의 즉시 | 연결 관리 · 재연결 · 분배 구현 |
| 긴급 경로 없음 (일배치만) | 가장 단순 | 가격 오류 · 리콜 · 분실 계정이 하루 지속 |
| ERP가 점포를 직접 호출 | 즉시 | 점포 인바운드 포트, 요청 방향 원칙 위반 |

**가격 · 판매 가능 여부 확정 시점**

| 선택지 | 장점 | 단점 |
|---|---|---|
| 스캔 시점에 확정, 이후 재검사 없음 | 결제 금액 = 장바구니 합계로 항상 일치. 단순. 현업 POS에 흔함 (**가정**) | 스캔 후 결제 전 몇 분 사이 도착한 변경은 반영 안 됨 |
| 결제 시작 시 재검사 | 직전 변경 반영 | 장바구니 수정 흐름 추가. 긴급 반영 자체가 최대 3분 지연이라 효과 작음 |
| 판매 확정 시 재계산 (ADR-0020) | — | 카드 승인 금액과 어긋남 |

## 결정
- **버전:** ERP 기준정보 변경마다 점포별 변경 순번(버전)을 매긴다 (유지).
- **일배치:** 점포 마감(ADR-0019) 후 점포 서버가 **다음 영업일 적용 기준정보 전체**를 요청하고, ERP는 요청 시점에 만들어 "버전 N까지 반영"을 표시해 돌려준다. 임시 테이블 적재 후 한 번에 교체하며, 실패하면 전날 데이터로 개시하고 알린다. 적용 직후 "버전 N 이후 변경분"을 한 번 받는다 (유지).
- **긴급 변경:** 점포 서버가 **3분 주기 폴링**으로 "마지막 적용 버전 이후 긴급 변경분"을 받아 반영한다 (주기 변경: 1분 → 3분). 주기는 설정값이다.
  - **긴급 대상은 4종으로 제한한다:** 긴급 판매 중지 · 가격 오류 정정 · 계정 긴급 차단 · 기기 긴급 사용 중지. 그 밖의 모든 변경은 일배치로 반영한다.
  - 폴링 요청은 **점포 서버 생존 신호**를 겸한다. ERP는 일정 시간 폴링이 없는 점포를 연결 끊김으로 본다 (기준 시간은 모니터링 설계에서 정함).
  - 긴급 변경도 ERP 원본을 고치므로 다음 일배치에 포함된다.
  - 계정 긴급 차단 · 기기 긴급 사용 중지를 받았을 때 진행 중인 결제는 마무리하고, 이후 새 거래 · 로그인 · 개점을 막는다 (ADR-0029와 같은 처리).
- **가격 · 판매 가능 여부는 스캔 시점에 확정한다** (변경). 스캔할 때 점포 서버의 현재 기준정보로 판매 가능 여부를 검사하고 가격을 장바구니 라인에 담는다. 이후 결제 시작 · 판매 확정 때 다시 검사 · 재계산하지 않으며, 결제는 장바구니 합계로 한다.
- **점포 서버 DB가 판매의 기준**이다. POS 클라이언트는 개점 시 점포 서버에서 오늘 데이터를 받아 화면을 구성한다 (유지).
- **웹소켓 긴급 전달은 확장**으로 둔다. 붙일 때는 연결을 점포가 열고, 같은 변경분 API로 재연결 후 따라잡는다.
- 일배치 전체 데이터가 현업에서 흔한 구성이라는 점은 **가정**이다 (유지).

## 대가와 후속 작업
- 긴급 변경은 최대 3분, 본사 회선 장애 중에는 복구 시까지 반영되지 않는다. 위해 상품 등은 본사가 매장에 직접 연락하는 업무로 보완한다 (**가정**: 현업 방식).
- 스캔 후 결제 전에 도착한 긴급 판매 중지 · 가격 정정은 그 장바구니에 반영되지 않는다.
- 긴급 변경이 POS 클라이언트 화면에 반영되는 방식은 POS_APP 레포에서 정한다.
- 계정 인증 정보 배포는 ADR-0029, 예정 가격은 미정 (ADR-0007 후속).
