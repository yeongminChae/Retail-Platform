# ADR-0009 POS_APP은 판매만 담당하고 ERP를 동기 호출하지 않는다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS 클라이언트, POS_APP, ERP

## 맥락
- 상품 · 재고의 원본을 ERP로 정했다 (ADR-0007, ADR-0008). ADR-0008에서는 매장 재고 조회를 POS_APP이 ERP API를 호출해 보여주기로 했다.
- 그 조회는 원래 카페 키오스크의 품절 여부 확인용으로 POS에 넣은 것이다.
- POS가 ERP를 응답을 기다리며 호출하면 ERP 지연 · 장애가 POS로 번지고, POS가 ERP 업무를 알게 된다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 조회 API 하나만 열어 둠 | 계산대에서 바로 재고 확인 | POS가 ERP 가용성에 묶이는 경로가 생김. 예외가 하나 생기면 계속 늘어남 |
| POS → ERP 동기 호출 금지, 판매 영역을 엄격히 정의 | 경계가 단순. ERP 장애가 판매에 영향 없음 | 재고 조회는 ERP 화면에서만 가능 |

## 결정
- **POS_APP은 ERP를 동기 호출하지 않는다.** 두 시스템의 연계는 두 방향뿐이다.
  - ERP → POS_APP: 기준정보 배포 (상품 · 가격 · 점포 · 기기 · 계산원)
  - POS_APP → ERP: 판매 결과 전달 (판매 확정 · 반품 · 마감). 전달은 판매 흐름을 막지 않는다.
- 판매 영역의 정의:

| 판매 영역 (POS_APP) | 판매 영역 아님 (ERP) |
|---|---|
| 장바구니 · 결제 · 판매 확정 · 반품 · 이상거래, 일마감 · 계산원 시재, 품절 표시(키오스크) | 기준정보 등록 · 수정, 재고 조회 · 조정 · 실사, 구매 · 입고, 월마감 · 대사 |

- 재고 조회는 ERP 화면에서만 한다. 이에 따라 ADR-0008은 ADR-0010으로 대체한다.
- 키오스크 품절은 재고 수량이 아니라 매장에서 켜고 끄는 **판매 가능 여부 표시**로 보고 판매 영역에 둔다. 카페에서 품절을 직원이 직접 지정하는 것이 일반적이라는 점은 **가정**이다.

## 대가와 후속 작업
- 계산대에서 재고를 바로 볼 수 없다. 필요하면 ERP 화면(읽기 전용 계정)을 쓴다.
- 판매 결과 전달 방식(이벤트 / API / 배치), 재전송 · 멱등 규칙은 연계 방식 결정에서 정한다.
- 품절 표시의 구체 설계(누가 켜는가, 키오스크 · 마트 POS 공용 여부)는 키오스크 설계에서 정한다.
