# ADR-0046 영수증번호는 거래 키와 따로 두고 발행일 기준으로 만든다

- 상태: 결정
- 날짜: 2026-11-26
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
- 고객이 문의할 때 가진 것은 보통 영수증(또는 카드사 알림 문자)이다. 전산 담당자는 그것으로 결제 상태를 찾아야 한다 (ADR-0026).
- POS_APP 확인 (2026-11-26, `main` `fc282eb`): `Sale.receiptNo` = `점포코드-오늘날짜(Asia/Seoul, yyyyMMdd)-POS번호-거래번호`로 만들어 `SALES.RECEIPT_NO`에 저장한다.
- 거래 키는 `점포-영업일-POS-거래번호`다 (용어는 ADR-0045). 영업일은 점포 마감 → 개시로 바뀌고 자정과 무관하다 (ADR-0018).
- 따라서 자정이 지나 점포 마감 전에 판매하면 영수증번호와 거래 키의 날짜가 다르다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 영수증번호 = 거래 키 (영업일) | 번호 하나 | 고객이 보는 날짜가 실제 날짜와 다를 수 있음 |
| 영수증번호를 따로, 발행일 기준 | 고객이 보는 날짜 = 실제 날짜. 현재 POS_APP 코드와 같음 | 영수증번호 → 거래 키 변환 시 영업일 후보가 둘 |

## 결정
- **영수증번호는 거래 키와 따로 관리한다.** 형식: `점포(4)-발행일(8)-POS(4)-거래번호(4)`. 예: `1000-20261126-0001-0199` (1000 점포, 발행일, 1번 POS, 199번 거래).
  - 발행일은 영수증을 발행한 달력 날짜(Asia/Seoul)다.
- POS_APP 안에서는 거래 키를 쓰고, 영수증번호는 영수증 출력과 고객 문의에 쓴다.
- 판매 결과 전송(ADR-0014)에 영수증번호를 함께 싣는다. ERP는 영수증번호로도 판매를 찾을 수 있다.
- **Payment는 영수증번호를 저장하지 않고 형식만 안다.** 운영 조회는 영수증번호를 받아 영업일 후보 **발행일 · 발행일 전날**로 거래 키를 만들어 찾고, 후보가 둘이면 둘 다 보여 준다 (PAYMENT-SIMULATOR `docs/phase2/03-운영-조회.md`).

## 대가와 후속 작업
- 영수증번호 형식을 바꾸면 Payment 운영 조회도 바꿔야 한다. 형식을 바꿀 때는 새 ADR로 한다.
- 점포가 이틀 이상 마감하지 않으면 영업일이 발행일보다 이틀 이상 앞설 수 있다. 미마감이면 다음 개시가 막히므로(ADR-0019) 보통 생기지 않는다고 본다. 생기면 거래 키로 찾는다.
- 영수증에 거래 키를 함께 인쇄할지, 영수증 바코드 내용은 POS_APP 레포에서 정한다.
