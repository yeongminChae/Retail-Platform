# ADR-0037 카드 취소는 결제 카드가 있어야 하고 이상거래 반환은 v1에서 업무로 처리한다

- 상태: 대체됨 (ADR-0038)
- 날짜: 2026-11-24
- 관련 시스템: POS 클라이언트, POS_APP, Payment Server, ERP
- 대체: ADR-0022

## 맥락
- PAYMENT-SIMULATOR 코드 확인 (2026-11-24, `main` `53f638d`):
  - **취소(`/cancel`)는 카드번호가 필수**다 (`CancelRequest.cardNo`). 받은 카드번호의 HMAC fingerprint를 원승인 카드와 비교하며 원문은 저장하지 않는다.
  - 망취소(`/reversal`) · 조회(`/inquiry`, `/cancel/inquiry`)는 카드번호를 받지 않는다.
- POS_APP은 카드번호를 저장하지 않는다 (ADR-0006). 따라서 나중에 취소하려면 카드를 다시 읽어야 한다.
- ADR-0022는 "v1에서는 관리자가 Payment Server 취소 API를 직접 호출한다"고 했으나, 카드 없이는 취소할 수 없어 실제 동작과 맞지 않는다.
- 돌려줘야 하는 돈은 **돈이 빠졌지만 어떤 확정 판매의 결제로도 쓰이지 않은 승인**이다. 예: 결과 불명 승인 후 다른 수단으로 재결제(이중 결제), 결제 포기 · 반품 · 재기동 후 취소 실패. ERP는 Payment 상태 전송의 "빠진 승인 목록"(ADR-0025)과 확정 판매에 기록된 승인을 비교해 이를 찾는다 (ADR-0027).
- 카드 없이 취소하는 운영 기능을 두면 "지인이 상품을 가져가고 내부 직원이 결제를 취소"하는 공모 위험이 생긴다.
- 현업은 VAN 자동 망취소 재시도, 판매에 쓰이지 않은 승인의 매입 제외, 고객 문의 시 VAN 가맹점 관리 화면 처리로 정리하는 경우가 많은 것으로 본다 (**가정**). PAYMENT-SIMULATOR에는 매입 · 정산이 없다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 카드 없는 운영 취소 추가 (전산 담당자 · 2인 승인 · 대상 제한) | 고객 재방문 없이 반환 | 기능 · 권한 · 승인 흐름 추가. 공모 위험 관리 필요. v1에는 과함 |
| v1은 카드 필수 유지, 반환은 업무 (고객 카드로 취소) | 카드 없는 취소가 없어 악용 위험 없음. Payment 변경 없음 | 고객이 다시 오지 않으면 돈이 묶임 |
| 매입 제외로 해결 | 취소 없이 청구되지 않음. 현업 방식에 가까움 (**가정**) | 매입 · 정산 기능이 없어 v1에서는 불가 |

## 결정
- **카드 취소에는 결제 카드가 필요하다** (현재 코드 그대로).
  - **고객 반품:** 결제 카드 지참 필수. 고객센터 POS에서 카드를 다시 읽어 취소하며, Payment Server가 원승인 카드와 같은지 확인한다.
  - **결제 포기 시 보상 취소:** 카드를 다시 읽는다 (고객이 계산대에 있음).
- **이상거래 · 대사 불일치의 반환은 v1에서 업무로 처리한다.**
  - ERP가 "돈이 빠졌지만 확정 판매에 쓰이지 않은 승인"을 찾아 목록에 올린다 (ADR-0027).
  - 담당자가 고객에게 안내하고, 고객이 결제 카드를 가지고 고객센터 POS에 오면 일반 카드 취소로 돌려준다.
  - **카드 없는 운영 취소는 두지 않는다.**
- **처리 기록 (ADR-0022 유지):** 확인 처리 시 처리 완료 여부 · 담당자 · 처리 업무(예: 카드 취소 / 조치 불필요 / 고객 미방문 / 기타) · 메모 · 일시를 ERP DB에 저장하고 감사 로그를 남긴다. ERP는 조치를 실행하지 않는다. 처리 완료는 ERP에만 기록하고 Payment Server의 `MANUAL_REVIEW`는 그대로 둔다.
- 결과 불명 건의 확정 · 조회는 그대로다: Recovery가 확정하고(ADR-0021), 즉시 확인은 전산 담당자가 Payment 운영 조회로 한다(ADR-0026).

## 대가와 후속 작업
- **알려진 한계:** 고객이 다시 오지 않으면 판매에 쓰이지 않은 승인이 고객 카드에 남는다. 안내 · 재연락 기준은 운영 절차로 둔다.
- 확장: 매입 · 정산 기능을 만들 때 "판매에 쓰이지 않은 승인은 매입에서 뺀다"를 넣는다 (`docs/backlog.md`). 카드 없는 운영 취소는 그때 필요하면 다시 본다.
- 단말 암호화(ADR-0006 2단계) 때 취소 요청의 카드번호도 암호화 대상에 넣는다.
- 결제 포기 · 반품 화면에서 카드를 다시 읽는 흐름은 POS_APP 레포에서 정한다.
