# ADR-0026 고객 문의 시 결제 상태는 담당자가 Payment Server 운영 조회로 즉시 확인한다

- 상태: 결정
- 날짜: 2026-11-20
- 관련 시스템: Payment Server, ERP

## 맥락
- ERP는 Payment Server가 5분마다 보내는 결제 상태를 받는다 (ADR-0025). ERP 화면은 최대 5분 늦다.
- 고객 컴플레인(예: "카드가 두 번 결제됐다")에는 즉시 확인이 필요할 수 있다.
- ERP는 다른 시스템을 호출하지 않는다 (ADR-0024). 실제 조치는 담당자가 Payment Server를 직접 쓰는 업무다 (ADR-0022).
- Payment Server에는 posTrx의 현재 상태만 읽는 API가 없다. `/inquiry`는 결과 불명 승인을 VAN에 묻는 용도다 (PAYMENT-SIMULATOR `main` 확인).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 담당자가 Payment Server 운영 조회를 직접 사용 | ADR-0024 유지. 현업 관행과 비슷 | 담당자가 ERP와 Payment 두 화면을 씀 |
| ERP에 즉시 조회 버튼 (ERP → Payment 호출) | 한 화면에서 해결 | ADR-0024 위반 |
| 전송 주기 단축 | 지연 감소 | 즉시는 아님. 이 용도 하나 때문에 전체 전송이 잦아짐 |

## 결정
- **ERP 전송 주기는 5분을 유지한다** (ADR-0025).
- 고객 문의로 즉시 확인이 필요하면 **담당자가 Payment Server의 운영 조회 기능으로 직접 확인**한다. ERP는 관여하지 않는다.
- 현업에서 VAN사 가맹점 관리 화면으로 조회하는 관행(**가정**)을 따른 것이며, Payment Server 운영 조회가 그 역할을 한다.
- 운영 조회는 posTrx별 현재 상태를 **읽기만** 하며, ADR-0025의 상태 합산 기준(빠짐 / 안 빠짐 / 미확정)을 그대로 쓴다.

## 대가와 후속 작업
- PAYMENT-SIMULATOR 과제: posTrx 상태 읽기 전용 조회 API. 운영 화면(GUI)은 필요해지면 그 위에 만든다 (`docs/backlog.md`).
