# ADR-0043 아웃박스는 성공할 때까지 재시도하고 순서를 보장하지 않으며 읽을 수 없는 건만 격리한다

- 상태: 결정
- 날짜: 2026-11-24
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
- 아웃박스: 보낼 데이터를 업무 데이터와 **같은 트랜잭션**으로 자기 DB의 "보낼 목록" 테이블에 적어 두고, 백그라운드 작업이 그 목록을 읽어 상대에게 보내는 방식. 업무 저장과 전송 기록이 함께 저장되거나 함께 실패하므로 "저장은 됐는데 안 보내짐" · "보냈는데 저장은 안 됨"이 생기지 않는다.
- 아웃박스를 쓰는 경로는 둘이다.
  - 점포 서버 → ERP: 판매 확정 · 반품 · 마감 요약 (ADR-0014, 0019)
  - Payment → ERP: posTrx별 결제 상태 (ADR-0025)
- ADR-0014는 재전송 간격 · 최대 지연 알림 기준 · 전송 순서 보장 여부 · 오래 실패한 건의 처리를 미정으로 두었고, 점포 서버의 전송 주기도 정하지 않았다.
- 점포 서버는 점포마다 따로 배포되어(ADR-0012) 점포마다 계약 버전이 달라질 수 있다.

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 재전송 | 간격을 늘리며(최대 5분) 성공할 때까지 | 데이터를 잃지 않음. ERP 복구 순간 몰림 완화 | — |
| | 고정 간격 | 단순 | 복구 순간 전 점포가 동시에 몰림 |
| 순서 | 보장 안 함, ERP가 도착 순서와 무관하게 저장 · 대사에서 짝 확인 | 한 건이 막혀도 나머지는 흐름. 대기 상태 불필요 | 짝이 맞는지는 다음 날 대사에서 확인 |
| | 보내는 쪽이 순서 보장 | ERP 단순 | 한 건이 계속 실패하면 그 점포 데이터 전체가 멈춤 |
| ERP 거부 | 읽을 수 없는 건만 거부, 내용 이상은 받고 표시 | 데이터를 잃지 않음 | 이상 데이터를 대사에서 처리 |
| | 검증 실패는 전부 거부 | ERP 데이터가 깨끗 | 거부된 데이터가 점포에 묶임 |

## 결정
- **재전송:** 실패하면 간격을 점점 늘려(예: 1초 → 2초 → 4초 …, 최대 5분) **성공할 때까지** 재시도한다. 포기하지 않는다.
- **순서는 보장하지 않는다.** 보내는 쪽은 만든 순서대로 시도하되, 한 건이 막혀도 다음 건을 보낸다. ERP는 **도착 순서와 무관하게 받은 그대로 저장**하고, 건끼리 짝이 맞는지는 **대사에서 확인**한다 (ADR-0027).
  - 원거래보다 먼저 온 반품: 그대로 저장, 원거래 번호로 나중에 연결. 재고는 반품 수신 시 반영.
  - 판매보다 먼저 온 마감 요약: 그대로 저장, 대사에서 비교.
  - Payment 결제 상태: 낮은 버전은 무시 (ADR-0025).
  - 다음 날까지 짝이 없으면 대사 불일치로 올린다.
- **ERP는 읽을 수 없는 건만 거부한다.** 형식이 깨졌거나, 필수 값(거래번호 · 점포 · 영업일 등)이 없거나, 지원하지 않는 계약 버전인 경우다. 모르는 코드 · 금액 불일치 같은 내용 이상은 **받아서 표시**하고 대사에서 처리한다.
- **격리:** 거부된 건(영구 실패)은 재시도하지 않고 **격리**해 다른 건을 막지 않게 하며 **즉시 알린다**. 전산 담당자가 원인(주로 배포 버전 불일치)을 고친 뒤 다시 보낸다. 중복 수신은 ERP가 성공으로 응답한다 (멱등, ADR-0014).
- **묶음 전송:** 한 번에 최대 100건까지 보내고, ERP는 **건별 결과**를 돌려준다. 성공한 건은 완료 처리한다.
- **전송 주기:**
  - 점포 서버: **5초마다 자기 아웃박스를 확인**해 쌓인 건을 보낸다 (자기 DB 확인이라 보낼 것이 없으면 요청이 나가지 않음). 사실상 거래 직후 몇 초 안에 도착한다.
  - Payment: 5분마다 (ADR-0025 유지).
- **알림:** 두 경로 모두 **가장 오래된 미전송 건이 30분을 넘으면** 알리고, **격리가 생기면 즉시** 알린다. 미전송 건수 · 가장 오래된 대기 시간은 모니터링 지표에 넣는다 (standards.md). 30분은 기준값이며 운영하며 조정한다.

## 대가와 후속 작업
- 전송 완료 건의 보관 기간 · 정리 주기는 각 레포에서 정한다.
- 계약 버전 규칙(호환 범위, 버전 올리는 방법)은 `contracts/` 작성 때 정한다.
