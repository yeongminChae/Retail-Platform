# retail-erp 2단계 상세 설계 (임시 위치)

`retail-erp` 레포가 생길 때까지 여기에 둔다 (CLAUDE.md 예외). 레포를 만들면 그 레포 `docs/`로 옮기고 여기서 지운다.

1단계 플랫폼 결정(`docs/summary.md`, ADR)을 기준으로 ERP 안의 설계(화면 · 테이블 · 내부 흐름 · 구현 작업)를 정한다. 시스템 간 결정이 바뀌면 새 ADR로 남긴다.

| # | 주제 | 상태 | 플랫폼 근거 |
|---|---|---|---|
| E01 | 수신 공통: 판매 · 반품 · 마감 요약 · 결제 상태 · 종료 신호 · 매입 결과 수신 규칙 (멱등, 버전, 거부 · 격리, 계약 버전) | 미정 | 0014, 0025, 0043, 0047, 0049 |
| E02 | 일 대사 · 불일치 목록 · 매입 제외 목록 생성 | 미정 | 0027, 0049 |
| E03 | 운영 요청 화면 · 반환 대상 판단 · 대기 목록 API · 종료 신호 처리 | 미정 | 0040, 0047 |
| E04 | 이상거래 · 처리 기록 | 미정 | 0021 |
| E05 | 기준정보 원본 · 배포 (상품 · 가격 · 점포 · 기기 · 계정, 일배치 · 긴급 4종), 가맹점 · 터미널 연결표 | 미정 | 0007, 0011, 0034, 0035, 0048 |
| E06 | 재고 원장 | 미정 | 0010 |
| E07 | 2단계 월마감 | 미정 | 0033, 0041 |
| E08 | 권한 · 감사 로그 | 미정 | 0036 |
| E09 | 정산 대사 (매입 결과 ↔ 입금) | 미정 | 0049 |

## 시작점

- ERP가 받은 과제 모음: `docs/phase2.md` "각 시스템이 받은 과제", `docs/summary.md` 7장.
- Payment와 맞물리는 API의 상대편 설계: PAYMENT-SIMULATOR `docs/phase2/` 02(결제 상태) · 04(운영 요청 · 종료 신호) · 06(연결표) · 07(매입 제외 · 매입 결과).
- 추천 순서: Payment 연동부터 (E01 → E02 → E03 → E09), 그다음 나머지.
