# ADR-0011 점포 · POS 기기 · 계산원은 ERP가 소유하고 점포 서버에는 자기 점포분만 내려준다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS_APP, ERP

## 맥락
- POS_APP은 계산원이 `"테스터"`로 고정돼 있고, v1에 계산원 마스터와 역할 3개(계산원 / 매장 관리자 / 본사)가 들어간다 (standards.md).
- 쓰기 작업은 ERP 화면에서 하고 POS는 판매만 한다 (ADR-0009). 계산원 · 관리자는 POS와 ERP 화면을 둘 다 쓴다 (ADR-0010).
- 거래번호 키에 POS 번호가 들어간다 (ADR-0002). 같은 번호를 두 단말이 쓰면 충돌한다.
- POS_APP은 점포마다 서버를 둔다 (ADR-0012).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| ERP 소유, 점포 서버에 자기 점포분 배포 | 기준정보 원본이 한 곳. 계정 하나로 POS · ERP 사용. POS가 ERP 업무를 모름 | 배포 지연 동안 신규 계산원 · 기기를 POS에서 못 씀 |
| POS_APP이 기기 · 계산원 소유 | POS 안에서 바로 등록 | ERP 화면용 계정이 따로 필요. POS에 쓰기 업무가 생겨 ADR-0009와 충돌 |

## 결정
- **점포 · POS 기기 · 계산원(계정 · 역할)의 원본은 ERP**이며 ERP는 전 점포 데이터를 가진다. 등록 · 수정 · 사용 중지는 ERP 화면에서 한다.
- **각 점포 서버(POS_APP)에는 자기 점포분만 내려준다.** 예: 111점 서버에는 111점 정보 · 111점 기기 목록 · 111점 소속 계정만.
- POS 기기 등록 항목: 점포 코드 · POS 번호 · 유형(일반 계산대 / 셀프 / 키오스크) · 사용 여부.
  - POS_APP은 **등록되어 있고 사용 중인 POS 번호만 개점**을 허용한다. 거래번호 충돌을 막는다.
  - ERP는 기기 목록으로 마감 누락(예: 사용 중 30대 중 29대만 마감)을 판단한다.
- **기기의 그날 운영 상태는 POS_APP 소유**다: 개점 · 마감 여부, 거래번호 순번, 계산원 시재.
- POS 로그인은 점포 서버가 내려받은 사본으로 처리한다 (ERP 호출 없음, ADR-0009).

## 대가와 후속 작업
- 기준정보 배포 방식 · 주기 · 지연 허용치는 연계 방식 결정에서 정한다 (ADR-0007의 상품 · 가격과 같은 경로로 맞춘다).
- 계정 인증 정보(비밀번호 해시 등)를 점포 서버에 어떻게 내려줄지, 퇴사자 계정 즉시 차단을 어떻게 보장할지는 미정.
- 물리 단말과 POS 번호를 묶는 방법(단말 인증)은 미정.
- 본사 역할의 권한 범위는 미정.
