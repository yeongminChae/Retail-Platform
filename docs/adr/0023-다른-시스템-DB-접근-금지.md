# ADR-0023 시스템은 자기 DB만 쓰고 다른 시스템 데이터는 API로만 접근한다

- 상태: 결정
- 날짜: 2026-11-20
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
이상거래 처리(ADR-0022)를 정하면서 "ERP가 Payment Server DB를 직접 수정"하는 안이 나왔다. ERP와 Payment Server는 같은 본사에 있어(ADR-0012) 기술적으로는 DB에 직접 붙을 수 있다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 자기 DB만, 다른 시스템은 API로만 | 각 시스템이 자기 데이터의 규칙(상태 전이 · 불변식)을 지킴. 스키마를 바꿔도 다른 시스템이 깨지지 않음 | 필요한 기능마다 API를 만들어야 함 |
| 필요하면 다른 시스템 DB 직접 읽기 · 쓰기 | 빠르게 붙음 | 불변식 우회(예: Payment의 취소 · 망취소 중 하나만 성공), 스키마 결합, 책임 불명 |

## 결정
- **각 시스템은 자기 DB만 읽고 쓴다.** 다른 시스템의 데이터는 그 시스템이 제공하는 **API로만** 접근한다. 읽기도 마찬가지다.
- DB 계정 · 네트워크도 시스템별로 분리해, 다른 시스템의 DB에 붙을 수 없게 한다.

## 대가와 후속 작업
- ERP가 필요한 Payment Server 데이터(예: `MANUAL_REVIEW` 목록, 결제 최종 상태)는 Payment Server API로 받아야 한다. 없는 API는 PAYMENT-SIMULATOR 과제로 만든다.
- 통합 실행 환경(compose)에서 DB를 하나의 PostgreSQL 인스턴스에 둘 경우에도 DB(또는 스키마) · 계정은 시스템별로 나눈다.
