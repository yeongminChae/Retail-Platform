# ADR-0013 판매 흐름은 ERP를 기다리지 않고 ERP 통신은 점포 서버의 백그라운드 작업으로만 한다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS 클라이언트, POS_APP, ERP
- 대체: ADR-0009

## 맥락
ADR-0009는 "POS_APP은 ERP를 동기 호출하지 않는다"로 정했다. 이후 배치 구조(ADR-0012)와 기준정보 배포(ADR-0015)를 정하면서, 점포 서버가 ERP에 먼저 요청하는 경로(일배치 수신 · 긴급 변경 폴링 · 판매 결과 전송)가 필요해졌다. 반대로 ERP가 점포 서버를 호출하게 하면 점포마다 외부에서 들어오는 포트를 열어야 한다. 바뀌지 않은 내용은 이 ADR에 다시 적는다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 점포 서버 → ERP 요청을 백그라운드 작업으로만 허용 | 요청이 늘 점포 → 본사 한 방향. 점포에 들어오는 포트 불필요. 판매는 ERP와 무관 | ADR-0009 문구 변경 필요 |
| ERP → 점포 서버 호출 (ADR-0009 문구 유지) | 점포 서버가 ERP를 호출하지 않음 | 점포마다 인바운드 포트, ERP가 전 점포 주소 · 재전송 관리 |

## 결정
- **판매 흐름(장바구니 · 결제 · 판매 확정 · 반품 · 마감) 안에서는 ERP 응답을 기다리지 않는다.**
- **ERP와의 통신은 점포 서버(POS_APP)의 백그라운드 작업으로만 한다.** 요청은 항상 점포 서버 → ERP 방향이다.
  - 기준정보 수신: 일배치 · 긴급 변경 폴링 (ADR-0015)
  - 판매 결과 전송: 판매 확정 · 반품 · 마감 (ADR-0014)
- **POS 클라이언트는 점포 서버하고만 통신한다.** ERP의 존재를 모른다.
- 판매 영역의 정의 (ADR-0009 유지):

| 판매 영역 (POS_APP) | 판매 영역 아님 (ERP) |
|---|---|
| 장바구니 · 결제 · 판매 확정 · 반품 · 이상거래, 일마감 · 계산원 시재, 품절 표시(키오스크) | 기준정보 등록 · 수정, 재고 조회 · 조정 · 실사, 구매 · 입고, 월마감 · 대사 |

- 재고 조회는 ERP 화면에서만 한다 (ADR-0010). 키오스크 품절은 판매 가능 여부 표시로 판매 영역에 둔다 (카페에서 직원이 직접 지정하는 것이 일반적이라는 점은 **가정**).

```text
POS 클라이언트 ──▶ 점포 서버(POS_APP) ──▶ Payment Server
                                      └──▶ ERP   (백그라운드 작업만)
```

## 대가와 후속 작업
- 점포 서버 → Payment Server 호출(ADR-0005)은 판매 흐름 안의 동기 호출이며 이 ADR의 대상이 아니다.
- 품절 표시의 구체 설계는 키오스크 설계에서 정한다.
