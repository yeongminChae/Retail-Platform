# ADR (Architecture Decision Record)

두 시스템 이상에 걸치는 결정을 하나에 한 파일로 기록한다. 한 시스템 안에서 끝나는 결정은 그 레포의 `docs/`에 둔다.

- 파일 이름: `NNNN-제목.md` (번호는 4자리, 순서대로)
- 상태: `제안` → `결정` → (`대체됨`)
- 결정을 바꿀 때는 기존 ADR을 고치지 않고 새 ADR을 만든다. 새 ADR에 `대체: ADR-NNNN`을 적고, 기존 ADR의 상태만 `대체됨 (ADR-MMMM)`으로 바꾼다.

## 템플릿

```markdown
# ADR-NNNN 제목

- 상태: 결정
- 날짜: YYYY-MM-DD
- 관련 시스템: POS_APP, Payment Server, ERP

## 맥락
무엇이 문제였고 왜 지금 정해야 했는가.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|

## 결정
무엇으로 정했는가.

## 대가와 후속 작업
이 결정으로 감수하는 것, 나중에 다시 볼 조건.
```
