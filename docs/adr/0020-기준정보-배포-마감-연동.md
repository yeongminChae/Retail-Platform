# ADR-0020 기준정보 일배치는 점포 마감을 계기로 받고 긴급 변경은 폴링으로 받는다

- 상태: 결정
- 날짜: 2026-11-18
- 관련 시스템: POS 클라이언트, POS_APP, ERP
- 대체: ADR-0015

## 맥락
ADR-0015는 점포 서버가 "정해진 시각"에 일배치를 받고 구체 시각은 일마감 설계에서 정하기로 했다. 일마감 설계(ADR-0019)에서 일배치를 시각이 아니라 점포 마감을 계기로 실행하기로 해 이 부분이 바뀌었다. 바뀌지 않은 내용은 이 ADR에 다시 적는다.

## 선택지
**일배치 실행 시점** (새로 정한 부분)

| 선택지 | 장점 | 단점 |
|---|---|---|
| 점포 마감을 계기로 실행, ERP는 요청 시 생성 | 마감이 늦어져도 꼬이지 않음. "다음 영업일 적용분"이 명확 | ERP가 요청 시점에 점포별 전체 데이터를 만들어야 함 |
| 정해진 시각 (예: 04:00) | 단순 | 그 시각까지 미마감이면 꼬임. 마감 여부 확인 필요 |

일상 반영 방식(일배치 전체 vs 변경분)과 긴급 변경 수신 방식(폴링 vs 웹소켓)의 비교는 ADR-0015 참고.

## 결정
- **버전:** ERP 기준정보 변경마다 점포별 변경 순번(버전)을 매긴다 (ADR-0015 유지).
- **일배치:** **점포 마감(ADR-0019)이 끝나면** 점포 서버가 ERP에 **다음 영업일 적용 기준정보 전체**를 요청한다 (변경). ERP는 요청 시점에 만들어 "버전 N까지 반영"을 표시해 돌려준다.
  - 적용: 임시 테이블에 모두 적재한 뒤 한 번에 교체한다. 실패하면 전날 데이터로 개시 · 판매를 계속하고 알림을 보낸다 (유지).
  - 적용 직후 "버전 N 이후 변경분"을 한 번 받아 생성과 적용 사이의 긴급 변경을 놓치지 않는다 (유지).
- **긴급 변경:** 점포 서버가 **1분 주기 폴링**으로 "마지막 적용 버전 이후 변경분"을 받아 반영한다 (유지).
  - 긴급 대상: 가격 오류 정정 · 판매 중지 · 계정 차단(퇴사 · 분실). 그 밖의 변경은 일배치로 반영한다.
  - 긴급 변경도 ERP 원본을 고치므로 다음 일배치에 자연히 포함된다.
- **점포 서버 DB가 판매의 기준**이다. POS 클라이언트는 개점 시 점포 서버에서 오늘 데이터를 받아 화면을 구성한다. 판매 확정 시 가격은 점포 서버가 다시 계산한다 (유지).
- **웹소켓 알림은 확장**으로 둔다 (유지).
- 일배치 전체 데이터가 현업에서 흔한 구성이라는 점은 **가정**이다 (ADR-0015 유지).

## 대가와 후속 작업
- ERP가 요청 시점에 점포별 전체 데이터를 만드는 비용은 다점포 확장 때 측정한다. 필요하면 미리 만들어 두는 방식으로 바꾼다.
- 긴급 변경이 POS 클라이언트 화면에 반영되는 방식은 POS_APP 레포에서 정한다.
- 폴링 주기 · 일배치 실패 알림 기준, 긴급 대상의 최종 목록은 ERP 설계에서 확정한다.
- 계정 인증 정보 배포 방식(ADR-0011 후속), 예정 가격(ADR-0007 후속)은 미정.
