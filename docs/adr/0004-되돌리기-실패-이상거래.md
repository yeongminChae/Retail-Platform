# ADR-0004 되돌리기가 3회 실패하면 이상거래로 저장하고 매장에서 고객을 보상한다

- 상태: 대체됨 (ADR-0021)
- 날짜: 2026-11-18
- 관련 시스템: POS_APP, Payment Server, ERP(대사)

## 맥락
망취소(ADR-0003) · 결제 포기 시 보상 취소 · 반품 카드 취소가 실패하거나 결과 불명이면, 손님 돈이 실제로 빠졌는지 POS가 확신할 수 없다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| POS는 보류, 확정은 Payment Server Recovery | 재시도 로직이 한 곳 | 판매 확정 후에도 보류 상태가 남음 |
| POS가 정책으로 시도 횟수를 제한하고 이상거래로 종결 | 판매 흐름이 항상 끝남. 운영 책임이 명확 | 이상거래를 사후에 닫는 운영 절차가 필요 |

## 결정
- **보류는 판매 확정 전(장바구니 단계)에만 존재한다.** 확정된 판매 · 실 결제에는 보류 상태를 두지 않는다.
- 되돌리는 거래는 최대 **3회** 시도한다. 그래도 실패하면 POS_APP에 **이상거래(`PAYMENT_ANOMALY`)**로 저장하고(원거래 · 결제 건 · 실패 사유 · 시도 횟수), 손님은 매장에서 보상한다.

## 대가와 후속 작업
- 이상거래를 닫는 화면과 Payment Server 거래와의 대사는 ERP 대사 설계에서 정한다.
- Payment Server Recovery가 나중에 같은 거래를 확정했을 때 이상거래와 어떻게 맞출지 정해야 한다.
