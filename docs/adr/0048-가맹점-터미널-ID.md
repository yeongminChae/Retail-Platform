# ADR-0048 가맹점 ID는 점포, 터미널 ID는 POS에 두고 Payment가 ERP에서 연결표를 가져와 검증한다

- 상태: 결정
- 날짜: 2026-11-27
- 관련 시스템: POS_APP, Payment Server, ERP
- 관련: ADR-0042 (주기 통신 추가), backlog "가맹점 ID · 터미널 ID"

## 맥락
- backlog: 승인에 가맹점 ID · 터미널 ID를 기록하고 취소 시 검증한다. 반품은 고객센터 POS에서 일어나므로(ADR-0031) 터미널은 "원승인과 같은 터미널"이 아니라 "그 가맹점에 등록된 터미널"로 검증하는 것을 검토했다.
- 가맹점 ID와 터미널 ID는 우리 점포코드 · POS 번호가 아니라 카드사 · VAN이 발급한 번호다 (**가정**, 국내 오프라인 결제의 일반적인 구조).
- Payment는 posTrx(ADR-0045)에서 점포 · POS를 알 수 있다. 남는 것은 점포 · POS → 가맹점 · 터미널 연결표다.
- 점포 · 기기 기준정보의 원본은 ERP다 (ADR-0011).
- 카페 · 소상공인 매장은 점포마다 사업자가 다를 수 있다 (backlog).

## 선택지
| 항목 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 단위 | 가맹점 = 점포, 터미널 = POS | 어느 POS인지 VAN까지 구분. 점포별 사업자 분리 가능 | 기기마다 터미널 등록 필요 |
| | 가맹점 = 본사, 터미널 = 점포 | 단순 | POS 구분 불가, 사업자 분리 불가 |
| 연결표 출처 | Payment가 ERP에서 가져옴 | 원본 한 곳. 기기 추가는 ERP에만 | 주기 통신 하나 추가 |
| | 점포 서버가 승인 요청에 실음 | 추가 통신 없음 | Payment가 값을 확인할 수 없음 |
| | Payment가 직접 관리 | 시스템 간 변경 없음 | 기기를 늘릴 때마다 두 곳 등록 |
| 취소 터미널 | 같은 가맹점의 등록 터미널 | 고객센터 POS 반품 가능 | 같은 가맹점 안에서는 어느 등록 터미널이든 취소 가능. 현업 관행인지는 미확인 |
| | 원승인과 같은 터미널 | 가장 엄격 | 고객센터 POS 반품이 막힘 (ADR-0031 충돌) |

## 결정
- **가맹점 ID는 점포마다, 터미널 ID는 POS(판매 · 고객센터)마다** ERP 점포 · 기기 정보에 둔다. 운영 전용 POS(ADR-0047)는 터미널 ID가 없다.
- **POS는 가맹점 · 터미널 값을 보내지 않는다.** Payment가 posTrx의 점포 · POS로 연결표에서 찾는다.
- **Payment가 ERP에서 연결표를 가져온다** (Payment → ERP 요청, ADR-0024 유지).
  - 하루 1회 전체, 그리고 5분 운영 요청 수집(ADR-0040) 때 마지막 버전 이후 변경분.
  - ERP가 응답하지 않으면 가진 사본으로 계속 처리한다.
- **승인:** 연결표에 없거나 사용 중지인 POS의 승인은 VAN 호출 없이 거부한다. 승인 시점의 가맹점 · 터미널 ID를 승인에 저장하고 VAN에 보낸다.
- **취소:** 가맹점 ID는 원승인과 같아야 하고, 취소한 POS는 그 가맹점에 등록된 사용 중 터미널이어야 한다. 운영 취소는 원승인의 터미널 ID로 보낸다.
- **주기 통신 추가 (ADR-0042 보완):**

| 경로 | 방식 | 주기 |
|---|---|---|
| Payment → ERP 가맹점 · 터미널 연결표 | 전체 1회 + 변경분 | 하루 1회 + 5분 (운영 요청 수집과 함께) |

## 대가와 후속 작업
- 새 기기는 ERP 등록 후 최대 5분 뒤부터 카드 결제가 된다. 개점 전 등록이 원칙이다.
- ERP 과제: 점포 가맹점 ID · 기기 터미널 ID 입력, 연결표 전체 · 변경분 응답 API.
- 매입 · 정산은 가맹점 ID별로 묶는다 (PAYMENT-SIMULATOR 07). 키오스크 · 소상공인 사업자 분리 때 가맹점 ID가 매출 귀속 키가 된다.
